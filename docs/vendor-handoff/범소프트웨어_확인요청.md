SAFE-LINK 네이티브 앱(iOS/Android) 제작 건으로, **기존 자산을 최대한 재사용**하는 방향에 맞춰 저희가 정리한 자료와 확인이 필요한 사항을 전달드립니다.

## 1. 저희가 제공하는 자산 (재사용 대상)
- **살아있는 웹앱**: `https://safe-link-v2.vercel.app` (현장 PoC 운영 중 — 전 기능 동작하는 레퍼런스)
- **소스 저장소**: `https://github.com/visionlab-coder/safe-link-v2`
- **이관 패키지 문서**: `docs/vendor-handoff/SAFE-LINK_VENDOR_HANDOFF.md`
  - API 명세(69개), Supabase 스키마·Realtime·RLS, 핵심 기능 플로우(인증/TBM/라이브통역/1:1/번역), 재사용 비즈니스 로직 인덱스(존댓말·다국어 발음·건설 용어 사전·STT/TTS 현장 튜닝값·20개 언어·권한모델), 환경변수 목록(이름만), 디자인 시스템
- **백엔드**: Supabase(PostgreSQL+Auth+Realtime+RLS) + Next.js API — 그대로 사용 가능
- **시크릿(API 키 등)**: 별도 보안 채널로 전달 예정(아래 5번)

## 2. 확인 요청 — 백엔드 범위 (가장 중요)
"각 API를 네이티브에 맞는 코드로 바꾼다"는 말씀을, 아래 중 무엇으로 이해하면 될까요?
- **(a)** Supabase/API **백엔드는 그대로 두고**, 네이티브는 그 API/Realtime를 호출하는 **클라이언트만 새로** 제작 → *저희 권장*
- **(b)** 백엔드(API 레이어)까지 리뉴얼·재작성
→ (a)/(b) 중 선택 + 백엔드를 새로 만든다면 어느 범위까지인지.

## 3. 확인 요청 — 웹앱 리뉴얼·저장소
- 웹앱 "고도화/리뉴얼"은 **저희 repo를 인수**해서 진행하시나요, 아니면 **별도로 새로** 구성하시나요?
- 리뉴얼 기간 중 **저희가 진행 중인 웹 작업(AI 엔진 개선·버그픽스 등)을 계속해도** 되나요, 아니면 **동결**(freeze)하고 넘길까요? (중복 수정 충돌 방지)

## 4. 확인 요청 — 현장 PoC 운영
- 네이티브 앱 납품 전까지 **현장 PoC는 저희가 현재 웹앱으로 계속 운영**하는 것으로 이해하면 될까요?
- PoC 운영을 위한 **운영 환경/DB는 현행 유지**(변경 최소화)로 가도 될지.

## 5. 확인 요청 — 계정·시크릿·일정
- **개발자 계정/서명**: Apple Developer·Google Play 개발자 계정, 서명 인증서, App Store Connect/Play Console 앱 레코드는 어느 쪽이 보유·관리하나요? (보통 벤더 또는 발주처)
- **시크릿 전달**: API 키/서비스 키는 **이메일 평문 금지** — 보안 채널(예: 1Password/암호화 파일/직접 환경변수 주입) 중 선호하시는 방식은?
- **일정**: 1차 인도 목표 시점과, **저희가 먼저 드려야 할 자료의 우선순위**(예: API 명세 먼저 / 스키마 먼저)를 알려주세요.
