# 【특약사항】

본 특약사항은 소프트웨어 개발 용역 계약서(BDS-2026-0621)의 일부를 구성하며, 본문 조항과 상충하는 경우 본 특약사항을 우선 적용한다.

**제13조 (과업 범위의 명확화)**
① 제2조 No.3~5(SAFE-LINK 코드 리뉴얼, 안드로이드·iOS 출시용 개발)의 구체적 기능 범위는 본 계약 **[별첨1 과업범위 명세]** 에 따르며, "을"은 별첨1에 기재된 기능을 **모두 구현·인도**한다.
② 별첨1과 본문이 상충하는 경우 **별첨1을 우선**한다.
③ "갑"이 제공하는 이관 패키지 문서(`SAFE-LINK_VENDOR_HANDOFF`)를 기능 기준의 참조자료로 한다.

**제14조 (백엔드 재사용)**
① "코드 리뉴얼"은 **기존 Supabase 백엔드 및 API를 유지·재사용**함을 원칙으로 하며, 백엔드 구조 변경이 필요한 경우 "을"은 "갑"의 사전 서면 동의를 받는다.

**제15조 (스토어 출시 및 심사 대응)**
① "출시용 개발"은 **Google Play 및 Apple App Store의 등록·심사 통과 및 게시까지 포함**한다.
② 심사 반려 시 "을"은 반려 사유에 대한 **무상 수정을 [3]회까지** 제공한다. 단, "갑"의 자료 미제공 등 갑 귀책 사유는 제외한다.
③ 개발자 계정·서명 인증서의 명의 및 비용 부담 주체는 **[갑 / 을]** 로 하며, 계정 권한은 최소 권한으로 부여한다.

**제16조 (검수 합격 기준)**
① 제6조의 검수 합격은 **안드로이드·iOS 각 실기기 1대 이상에서 별첨1의 핵심 기능(특히 라이브 통역의 실시간 음성→번역→음성)이 정상 동작**함을 "갑"이 확인하는 것을 기준으로 한다.
② 제6조②의 검수기간은 "을"이 **검수 가능한 빌드(설치파일 또는 테스트 배포)를 "갑"에게 인도한 날**부터 기산한다.
③ 핵심 기능 미동작은 검수 불합격으로 보며, "을"은 계약 범위 내에서 이를 보완한다.

**제17조 (지식재산권 보충)**
① **SAFE-LINK 기존 코드 및 본 계약에 따른 리뉴얼·파생 결과물의 저작권·지식재산권은 "갑"에게 귀속**한다. 제9조②의 "을 보유 자산"은 SAFE-LINK와 무관한 **범용 라이브러리·프레임워크에 한**한다.
② "을"은 결과물에 제3자 라이선스 충돌이 없도록 하며, 사용한 **오픈소스·라이브러리 목록과 라이선스를 납품 시 제출**한다.

**제18조 (개인정보 처리 위탁)**
① "을"은 본 과업 수행을 위하여 "갑"의 **근로자 개인정보를 처리하는 수탁자**로서, **개인정보 보호법 제26조** 및 관계 법령에 따른 안전조치 의무를 이행한다.
② "을"은 위탁받은 개인정보를 본 계약 목적 외로 이용하거나 제3자에게 제공·재위탁하지 아니하며, 재위탁이 필요한 경우 "갑"의 사전 서면 동의를 받는다.
③ **API 키 등 시크릿 및 개인정보는 보안 채널로만** 전달·보관하며, **계약 종료 시 즉시 파기**하고 그 사실을 "갑"에게 통지한다.
④ "을"의 위반으로 개인정보 유출 등 손해가 발생한 경우 "을"이 배상 책임을 진다.

**제19조 (재위탁 제한)**
① "을"은 "갑"의 **사전 서면 동의 없이** 본 과업의 전부 또는 일부를 제3자에게 재위탁하지 아니한다.

**제20조 (납기 지연 배상)**
① "을"의 귀책사유로 납기가 지연되는 경우, "을"은 지연일수에 대하여 **지체상금(지연일수 × 해당 과업 대금 × [0.1]%)** 을 "갑"에게 지급한다. (상한 [해당 과업 대금의 10]%)

**제21조 (대금 지급 구조 — 제4조 보충)** *[선금 비중 협상 시]*
① 대금은 **착수금 [40]% / 잔금 [60]%** 로 하며, 잔금은 제16조 검수 합격 후 [14]영업일 내 지급한다. (협상 결과 반영; 미협상 시 본문 제4조 유지)

**제22조 (PMS·개발교육 항목)** *[유지 시]*
① 제2조 No.1(PMS), No.2(개발 교육)는 SAFE-LINK와 별개 과업으로, 각 **산출물·범위·검수기준을 [별첨2]에 명시**한다. 불요 시 본 계약에서 제외하고 계약금액을 조정한다.

**제23조 (우선순위)** 본 특약사항이 본문 조항과 상충하는 경우 본 특약사항을 우선한다.

# 【별첨1 — SAFE-LINK 과업범위 명세】

대상: SAFE-LINK 안드로이드·iOS 출시용 앱 + 기존 솔루션 코드 리뉴얼. 세부 구현 기준은 갑 제공 이관 패키지(`SAFE-LINK_VENDOR_HANDOFF`) 및 살아있는 웹앱(`safe-link-v2.vercel.app`).

## A. 공통 기능 (안드로이드·iOS 양 플랫폼 모두)
1. **인증/로그인**: 관리자 이메일 로그인, 근로자 이니셜+휴대폰 뒷4자리 빠른 로그인, QR/NFC 진입, 세션 유지·자동 갱신, 복수 현장 선택.
2. **TBM 브로드캐스팅**: 관리자 발송 → 근로자 **실시간 수신 + 알림**, 다국어 표시.
3. **TBM 서명**: 내용 다국어 번역 표시, 음성 청취(TTS), **서명 입력·제출**, 확인 기록.
4. **라이브 통역**(핵심): 실시간 음성 입력(STT) → 번역 → 음성 출력(TTS), **양방향**(관리자↔근로자), 다국어, 음성구간감지(VAD), 자막.
5. **1:1 대화**: 관리자↔근로자 **실시간 채팅**, 음성 입력·번역·발음, 온라인 상태 표시.
6. **NFC/QR 출입**: 스캔, 현장 출입 체크인/아웃, 지오펜스(위치) 검증.
7. **다국어**: **16개국어 이상** UI 및 통·번역(웹앱 지원 언어 동등).
8. **알림**: TBM·메시지 수신 시 기기 알림(푸시 또는 로컬).
9. **오프라인/네트워크 실패 처리**: 실패 시 사용자 안내 및 복구 경로.

## B. 코드 리뉴얼 (No.3)
- 기존 SAFE-LINK 웹/백엔드 자산 재사용을 전제로 한 정리·개선. **Supabase/API 백엔드 유지**(제14조).
- 범위 세부는 갑·을 착수 협의로 확정하되 본 명세를 하한으로 한다.

## C. 비기능 요건
- **백엔드**: 기존 Supabase + API 재사용(신규 백엔드 구축 시 사전 동의).
- **디자인**: 갑 디자인 시스템(`DESIGN.md`) 준수 — 다크/글래스모피즘, 대형 터치타깃, 다국어 폰트.
- **스토어**: Play/App Store 심사 통과·게시(제15조).
- **보안/개인정보**: 제18조 준수.

## D. 인수(검수) 체크리스트 — 각 항목 실기기 동작 확인
- [ ] 관리자 로그인 / 근로자 빠른 로그인 (Android/iOS)
- [ ] TBM 발송 → 타 기기 실시간 수신 + 알림
- [ ] TBM 다국어 번역 표시 → 서명 제출 → 기록
- [ ] **라이브 통역 양방향**(2대): 음성→번역→음성 (Android/iOS)
- [ ] 1:1 대화 음성·번역 송수신
- [ ] QR/NFC 출입 (지오펜스 포함)
- [ ] 다국어 16개국어 전환
- [ ] 알림 수신 / 오프라인 안내
- [ ] Play·App Store 심사 통과·게시
