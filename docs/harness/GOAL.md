# GOAL

## One-line Goal

기존 SAFE-LINK 웹 서비스를 재사용해 현장 관리자와 근로자가 Android/iOS에서 TBM 전달·확인·서명·번역 채팅을 안정적으로 수행할 수 있는 상용 앱을 만든다.

## Why This Matters

공통 코드를 직접 구축하면 외주 범위를 네이티브 검수·스토어 심사·상용 안정화로 축소할 수 있다. 비용을 줄이되 안전 기록, 개인정보, 현장 통신 실패를 데모 수준으로 처리하지 않는 것이 핵심이다.

## Primary User / Buyer / Operator

- 사용자: 현장 관리자, 외국인 근로자
- 구매·운영 주체: 현장 및 본사 안전 담당 조직

## Production Context

불안정한 네트워크와 다양한 Android 단말이 존재하는 건설현장이다. 다국어 음성·번역, 서명, QR/NFC, 푸시알림, 개인정보와 안전 증거 기록을 다룬다.

## Wedge

이미 구현된 TBM 생성·전달·서명·번역 채팅과 Supabase 데이터 계층을 유지하고, Capacitor 계열의 얇은 네이티브 셸을 우선 검토한다.

## Architecture Decision (2026-06-22, 사용자 지시 반영)

**단일 앱 = 배포된 웹앱 전체를 first-party WebView로 호스팅.** 관리자·근로자 모두 한 앱에서 웹앱 로그인으로 전 기능을 사용한다(feature별 네이티브 재구현 아님). 근거: ① "웹앱의 모든 기능을 하나의 앱에, 관리자·근로자 모두 한 앱" 요구, ② 라이브 통역·1:1 대화 로직은 보호 대상 PoC 파일에 있어 재구현 시 divergence 위험 → 웹 코드 100% 그대로 재사용이 "절대 안 깨짐"을 최대 보장, ③ Capacitor `server.url`로 즉시 전 기능 확보. 네이티브 역할 = 마이크/카메라/알림 권한 grant, (후속) QR/NFC·푸시·딥링크·오프라인. 기존 로컬 SPA 패널(M-005~M-010)은 폴백/진단용으로 보존.

**최우선 핵심(사용자 명시)**: TBM 브로드캐스팅 · 라이브 통역 · 1:1 대화. 이 3종이 모바일 가치의 핵심.

## Top-Priority Done Bar (MC track) — 핵심 기능 2대 실기기 검증 완료 (2026-06-22~23)

- [x] WebView에서 Supabase 세션 인증이 지속된다 — Android 실기기 PASS. 게이팅 검증 통과.
- [x] 관리자·근로자 모두 한 앱에서 로그인·전 기능 접근 — 2대 실기기 확인.
- [x] 라이브 통역이 실기기에서 동작한다(STT→번역→TTS) — 2대 양방향 기능 정상.
- [x] TBM 브로드캐스팅이 실기기에서 수신된다 — 동작 확인.
- [x] 1:1 대화가 실기기에서 동작한다 — 동작 확인.

> **알려진 품질 이슈(기능 아님)**: 한국어 출력에서 "갑니다" → "갑시습니다" 등 일부 어미 변형. STT 인식/정규화/TTS 발음 중 한 단계의 artifact로 추정 — 진단 후 안전 범위에서 수정(PoC 무중단). 별도 증분 Q-001.
