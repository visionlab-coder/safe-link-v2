## 범위와 사용 순서

- 관리자 TBM 작성 화면에서 'TBM 실시간 방송 · 종료 후 자동 요약' 진입.
- /admin/live?mode=tbm 에서 방송 시작. 근로자는 기존 /worker/live에서 청취.
- 종료 시 마지막 녹음 처리와 원문 저장을 기다린 후 방송 종료 및 요약 요청.
- 기존 서버 OPENAI_API_KEY / OPENAI_TEXT_MODEL 사용. STT·번역·TTS 공급자는 변경하지 않음.
- 요약은 기존 published TBM으로 저장. 근로자 라이브 화면에 해당 TBM ID로 이동하는 확인·서명 링크 표시. 기존 TBM 상세의 번역 및 서명 절차 사용.
- 일반 /admin/live 종료와 기존 수동 TBM 전파는 자동 요약하지 않음.

## 데이터 및 안전 경계

- V031 migration: live_tbm_summaries에 방송 ID, 원문 스냅샷, 요약, 모델, TBM ID 저장.
- 요청자의 현장 권한, 방송 소유자, 종료 상태 검증. 소유자의 해당 방송 원문만 요약.
- 방송 행 잠금 + 세션별 PK + TBM idempotency key로 중복 전파 방지.
- 생성/저장 실패 시 트랜잭션 롤백. 성공 커밋 후에만 SSE 알림.
- 빈 발화, 60,000자 초과 원문, 누락된 원문 저장은 발송하지 않음. 안전 내용을 조용히 잘라내지 않음.
- 정상 저장된 원문은 요약 실패 후 재시도에 사용. 원문 저장 자체가 실패하면 자동 재시도 발송 금지.
- 사용자 승인에 따라 원문을 외부 OpenAI에 전송. 키는 서버에만 존재. Responses store=false.
- AI 요약/서명 기능 구현이 법적 증명력 또는 안전교육 내용의 정확성을 보장하는 것은 아님.
