# SQ Link V3 운영 용량 계획

측정일: 2026-08-05 (Asia/Seoul)

## 현재 사용량

| 항목 | 측정값 | 운영 기준 |
|---|---:|---|
| EC2 루트 디스크 | 28 GB 중 11 GB 사용(39%), 18 GB 여유 | 70% 경고, 85% 긴급 |
| PostgreSQL | 36 MB | 일별 크기와 주간 증가량 기록 |
| Redis | 1.29 MB, 4 keys | 메모리와 key 수를 감시하고 세션·quota 장애 여부 확인 |
| Object Storage | 약 1.2 MB | 일별 object 수·bytes와 실패율 기록 |
| DB 일일 백업 | 최근 약 4.5 MB | 매일 03:00 KST, 14일 보관 |

최근 DB 백업은 2026-07-30의 약 4.50 MB 이후 2026-08-04의 약 4.51 MB까지 큰 증가가 없었다. 이 값은 오픈 전 데이터 기준이므로 실제 운영 첫 달에는 주 단위로 다시 산정한다.

## 경고·증설 기준

- 디스크 사용률 70% 또는 60일 예측치가 70%에 도달하면 EBS 증설을 계획한다.
- 디스크 사용률 85%에서는 신규 대용량 업로드를 제한하고 즉시 증설·로그/백업 정리를 수행한다.
- PostgreSQL은 일주일 증가량이 20%를 넘거나 5 GB를 넘으면 인덱스·보관 정책과 인스턴스 사양을 재검토한다.
- Object Storage가 10 GB를 넘거나 주간 증가율이 20%를 넘으면 S3/R2 등 외부 저장소 이전 또는 용량 확장을 검토한다.
- Redis는 현재 `maxmemory=0`, `noeviction`이므로 호스트 메모리 고갈 위험이 있다. 운영 트래픽 증가 전 전용 메모리 한도와 세션 보호 정책을 정하고, 사용량 70% 경고·85% 긴급 알림을 설정한다.
- 일일 백업 실패, DB dump와 object archive 중 하나라도 누락, SHA-256 manifest 불일치는 즉시 장애로 처리한다.

## 점검 주기와 담당

- 매일: 백업 성공 시각·파일 크기·SHA-256 manifest 확인
- 매주: EC2 디스크, PostgreSQL, Redis, Object Storage 사용량 기록
- 매월: 30일 증가량으로 3개월 용량을 재예측하고 증설 여부 결정
- 담당: 개발 운영 담당자, 장애 연락망 김무빈
