# DeepL 원문 우선 적용 — 2026-10-28

## 목표 / 수락 기준

- 사용자 요청: 가꾸목뿐 아니라 표준어 병합으로 충돌한 항목도 원래 입력 단어에 지정된 DeepL 번역을 적용하고 운영 배포한다.
- 한국어 표시·정규화·권한은 유지한다. 영어/일본어/베트남어/중국어 번역 입력만 검증된 원문을 사용한다.
- 다른 언어, 일반 문장 보호(들어가도/시작합시다), 기존 기록은 그대로 둔다.

## 확인된 원인 / 구현

- 가꾸목과 가쿠목이 모두 각목으로 정규화되지만 DeepL 원본의 번역은 서로 다르다. 이전 연결 사전은 충돌 별칭 각목을 제외했으므로 일반 번역 Lumber가 출력됐다.
- 공통 정규화기는 한국어 표시값과 번역 입력값을 별도로 만든다. 충돌 18개 원어는 번역 입력에 보존한다. 현재 사전의 표준어가 검토 스냅샷과 일치할 때만 적용한다.
- 음성의 originalTranscript를 채팅·라이브·TBM에 전달한다. 제공된 원문과 표시문을 같은 한국어 규칙으로 정규화해 일치할 때만 원문 증거를 사용한다. 수동 수정으로 달라진 문장은 역으로 추측하지 않는다.
- TBM source_text와 normalized_text를 구분해 저장한다. 라이브 이벤트 translations.__sq_source는 원문 메타데이터이며 번역 언어가 아니다. V047은 편집 초안의 원문 보존용 nullable source_text만 추가한다.
- 원본 DeepL 사전은 수정하지 않는다. 새 연결 사전은 원본에 직접 등록된 단어를 파생 별칭보다 우선하며, 원본이 없는 충돌 표준어는 임의로 한 번역을 선택하지 않는다.

## 배포 / 복구 경계

- AWS만 정상 CI 절차로 배포한다. 온프레미스, DNS, 계정, 모바일 APK 변경은 제외.
- configure-deepl-source-bridge.py가 기존 env를 root 전용 /etc/safelink/deepl-source-before-20261028/에 백업한다. API 키는 출력하지 않는다.
- 이전 릴리스 b45de763cd3d2619c9356c0ff245eb129ca4667b와 이전 연결 사전으로 복구 가능. 추가된 nullable DB 열은 이전 코드에 영향을 주지 않는다.
- 과거 메시지와 이미 생성된 번역은 소급 수정하지 않는다. 원문이 없는 과거 각목 기록에서 가꾸목/가쿠목을 추측할 수 없다.
- 요약으로 다시 작성된 문장에는 원문 용어를 억지로 삽입하지 않는다. 본문/원문 번역과 요약은 별도다. 실제 휴대폰 음성인식 정확도는 이번 텍스트·API 검증과 별도다.
