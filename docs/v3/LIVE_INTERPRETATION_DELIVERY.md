# 라이브 통역 전달 기준 (2026-09-08)

- 관리자 `/admin/live`에서 방송 시작 → 같은 현장 근로자 `/worker/live`에서 수신.
- 방송 중 짧은 쉼(600ms)을 감지하면 자동 전송. 분당 30회 STT 제한을 유지하기 위해 최소 청크 길이는 2.1초, 연속 발화는 최대 4초마다 분할한다.
- 근로자의 관리자에게 말하기도 같은 분할 기준을 사용한다. 전송마다 버튼을 누를 필요는 없다.
- 이는 짧은 오디오 구간을 순차 전달하는 방식이며 지연 0초인 단어 단위 스트리밍은 아니다. STT/번역/TTS 처리 및 네트워크 시간이 추가된다.
- 기존 관리자 1.5초 타이머는 무음 포함 최대 40회/분 요청하여 30회 제한과 충돌했다. 무음·재생 음성 오염 청크를 제외하고 요청 빈도를 줄인다.
- 캡처 순서로 STT 결과를 전달하며 방송 종료 신호는 마지막 발화 저장 이후 보낸다.
- SSE 응답은 Next.js와 백엔드에서 `X-Accel-Buffering: no`를 설정한다. 실제 프록시가 이를 무시하는 경우 별도 운영 설정 점검이 필요하다.
- 휴대폰 OS가 백그라운드 마이크/브라우저를 중단하는 동작까지 보장하지 않는다. 화면을 열고 마이크 및 오디오 재생 권한을 허용한 상태로 테스트한다.

## 검증

`node scripts/live-capture-test.mjs`: 실제 hook을 가짜 마이크/타이머/API로 실행. 방송 종료 전 전송, 무음 미전송, 연속 발화 반복 전송, 응답 순서, 재생음 제외, 이탈 후 결과 제외, 종료 전 마지막 발화 전달 검증.

`node scripts/vad-decision-test.mjs`: 기존 음성 구간 판정 회귀 테스트.

자동 테스트는 실제 Flitto 응답속도, 운영 프록시, Android 오디오까지 검증하지 않는다. 배포 후 PC 관리자와 휴대폰 근로자로 20초 연속 발화 중 첫 번역이 도착하는지, 멈춘 뒤 마지막 문장이 한 번만 전달되는지 확인해야 한다.
